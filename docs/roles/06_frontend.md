# Роль 6. Frontend

**Цель:** веб-интерфейс, через который человек без знания SQL задаёт вопросы, отвечает на уточнения и видит ответ, SQL, отчёт проверки, таблицу и график.
**Зависит от:** роль 3 (API + SSE-заглушка). Подключение к реальному агенту — после роли 5.
**Нужно для:** пользовательского тестирования, демо на защите.

Контракты: [`CONTRACTS.md` §1–2](../CONTRACTS.md).

## Стек
Next.js (App Router) · TypeScript · Tailwind CSS · shadcn/ui · TanStack Query · Recharts · `@microsoft/fetch-event-source` (SSE через POST с заголовком авторизации; стандартный `EventSource` не умеет ни POST, ни заголовки) · `openapi-typescript` (типы из Swagger бэкенда) · Playwright (e2e).

## Задачи

### 6.1 Каркас
- [ ] Проект Next.js, Tailwind, shadcn/ui, тёмная и светлая темы
- [ ] Генерация типов API: `pnpm gen:api` → `src/lib/api/schema.d.ts` из `http://localhost:8000/openapi.json`
- [ ] API-клиент с JWT (httpOnly cookie через route handler Next.js или `localStorage` для MVP), редирект на `/login` при 401

### 6.2 Страницы

| Маршрут | Содержимое | Роль |
|---|---|---|
| `/login`, `/register` | Формы | — |
| `/datasources` | Список источников со статусом (`indexing` с поллингом / `ready` / `error`), форма подключения, кнопка «Переиндексировать» | admin (список видят все) |
| `/datasources/[id]` | Обозреватель схемы: таблицы, столбцы, типы, комментарии, FK | any |
| `/chat` | Выбор источника → новая сессия | any |
| `/chat/[sessionId]` | Основной экран чата | owner |

### 6.3 Экран чата (главная часть)
- [ ] Боковая панель сессий, создание новой сессии
- [ ] Лента сообщений, ввод с `Enter` / `Shift+Enter`, блокировка ввода во время потока, кнопка «Остановить» (abort)
- [ ] **`AgentProgress`**: живая лента шагов по событиям `step` («Ищу таблицы…» → «Проверяю SQL…» → «Выполняю…»)
- [ ] **`ClarificationCard`**: вопрос, по каждой неоднозначности кнопки-варианты с описанием и поле «свой вариант», кнопка «Продолжить» → `POST /clarify` → продолжение потока в той же карточке ответа
- [ ] **`AssistantAnswer`** (вкладки или аккордеон):
  - текстовое пояснение (стриминг `answer`)
  - **`ChartView`** по `ChartSpec` (Recharts: bar, line, pie, scatter)
  - **`ResultTable`**: сортировка, пагинация на клиенте, плашка «показаны первые N строк», если `truncated`, экспорт CSV
  - **`SqlPanel`**: подсветка синтаксиса (`shiki` или `prism`), копирование, номер попытки (если была самокоррекция)
  - **`ValidationReport`**: 5 уровней в виде бейджей ✅/❌ с `message` по наведению; при блокировке выделен уровень, на котором остановлен запрос
- [ ] Отказы и ошибки (`error`) показываются отдельной карточкой с понятным текстом, а не тостом
- [ ] Обратная связь 👍/👎 + необязательный комментарий → `POST /feedback`
- [ ] Восстановление истории: `GET /sessions/{id}/messages` рендерит те же компоненты из сохранённых полей; незавершённое уточнение остаётся активным

### 6.4 Обработка SSE
- [ ] Хук `useAgentStream(sessionId)` превращает события в состояние сообщения (reducer по `event`)
- [ ] Неизвестные события игнорируются (совместимость вперёд), обрыв соединения → `error` с кнопкой «Повторить»
- [ ] Режим разработки работает против `FakeAgentRunner` бэкенда, поэтому весь UI можно сделать до готовности агента

### 6.5 Качество
- [ ] Адаптивность до ширины 375 px (таблица со скроллом внутри карточки)
- [ ] Доступность: фокус, `aria-label` на иконках, контраст
- [ ] e2e (Playwright): логин → подключение источника → вопрос → уточнение → ответ с таблицей и графиком; вопрос «удали все заказы» → карточка отказа
