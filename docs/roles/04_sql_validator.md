# Роль 4. SQL Validator

**Статус: ✅ выполнена** (октябрь 2026). Правила, обоснования и результаты — в [docs/validator.md](../validator.md) (основа для главы 2 диплома).

**Цель:** детерминированный модуль `app.validator`, который гарантирует, что до выполнения доходит только безопасный, синтаксически корректный и согласованный со схемой `SELECT`. Это ядро научной части диплома, поэтому модуль покрывается тестами плотнее остальных.
**Зависит от:** роль 2 (`s2d_reader`), роль 3 (`SchemaSnapshot`, пулы соединений).
**Нужно для:** AI Agent (узлы `validate_sql`, `execute`), Evals (метрика unsafe block rate).

Интерфейс — [`CONTRACTS.md` §3](../CONTRACTS.md#3-валидатор-sql).

## Задачи

### 4.1 Уровень 1 — синтаксис
- [x] `sqlglot.parse(sql, read="postgres")`, ошибка с номером строки, позиции и фрагментом
- [x] Ровно одно выражение, иначе `fatal`. Голый `SELECT` без столбцов отклоняется
- [x] Неразобранная конструкция не выполняется (allowlist по парсеру)

### 4.2 Уровень 2 — политика read-only (`fatal`)
- [x] Корень — только `SELECT`/`UNION`/`INTERSECT`/`EXCEPT`. sqlglot разбирает `LISTEN ch` и `TABLE orders` как выражение с псевдонимом, поэтому корень проверяется явно
- [x] 28 запрещённых типов узлов по всему дереву, включая изменяющие CTE, `SELECT INTO`, `FOR UPDATE/SHARE` и служебные `Command`
- [x] 36 префиксов опасных функций: задержка, файлы сервера, `dblink`, управление сессиями, `query_to_xml`, последовательности, транзакции, блокировки, репликация
- [x] Системные каталоги: `pg_catalog`, `information_schema`, `pg_toast`, неквалифицированные `pg_*`
- [x] Регистр, кавычки и комментарии не помогают: проверка идёт по AST

### 4.3 Уровень 3 — сверка со схемой
- [x] Существование таблиц (с учётом `search_path`) и столбцов (`sqlglot.optimizer.qualify`), однозначность ссылок
- [x] Подсказки: похожие имена таблиц и столбцов, столбцы с тем же именем в других таблицах, указание на неоднозначность
- [x] Идентификаторы без кавычек приводятся к нижнему регистру, как в PostgreSQL. Без этого `SELECT … FROM ORDERS` ложно блокировался: нашёл property-based тест
- [x] Строка, сравниваемая с датой, должна быть датой. Изначально планировалось предупреждение, но PostgreSQL такой запрос всё равно отвергнет, поэтому это ошибка с подсказкой (`date_trunc(…)`)
- [x] Нормализация: комментарии удаляются, внешний `LIMIT` ≤ `max_rows + 1`

### 4.4 Уровень 4 — EXPLAIN
- [x] `EXPLAIN (FORMAT JSON)` без `ANALYZE`, в read-only транзакции с тайм-аутом
- [x] Порог стоимости `SQL_MAX_EXPLAIN_COST`
- [x] Детектор декартова произведения (`Nested Loop` без условия соединения, обе стороны > 10 000 строк). Самосоединение по ключу не срабатывает (тест)
- [x] Ошибки планировщика → `passed=False` с текстом PostgreSQL
- [ ] ~~`SQL_MAX_EXPLAIN_ROWS`~~ — не нужен: результат ограничен `LIMIT`, а большие промежуточные выборки отражаются в стоимости

### 4.5 Уровень 5 — изолированное выполнение
- [x] `BEGIN READ ONLY` → `SET LOCAL statement_timeout`, `idle_in_transaction_session_timeout` → курсор на `max_rows + 1` строк → `ROLLBACK`
- [x] JSON-сериализация: `numeric` → число (графики), даты → ISO, `bytea`, `uuid`, массивы, `json`
- [x] Ограничение размера ответа 2 МБ → `truncated`
- [x] `ExecutionError` с `ValidationLevelResult` уровня 5: тайм-аут, ошибки выполнения

### 4.6 Тесты
- [x] **88 атак** в [`evals/datasets/unsafe/sql_attacks.jsonl`](../../evals/datasets/unsafe/sql_attacks.jsonl), 9 категорий (DDL, DML, несколько выражений, изменяющие CTE, `INTO`/блокировки, служебные команды, опасные функции, системные каталоги, обфускация) — 100% заблокированы на уровнях 1–2
- [x] **42 безобидных запроса** в [`sql_benign.jsonl`](../../evals/datasets/unsafe/sql_benign.jsonl) — 0 ложных блокировок. Все проходят уровни 1–5 на настоящей демо-БД
- [x] Тесты уровня 3 с проверкой подсказок
- [x] Интеграционные тесты уровней 4–5 на тестовой целевой БД (20 000 строк): декартово произведение, порог стоимости, ошибка планировщика, тайм-аут, усечение по строкам и байтам, `DELETE` под суперпользователем не проходит из-за read-only транзакции
- [x] Property-based (hypothesis, 300 примеров): опасные фрагменты в любом месте допустимого запроса
- [x] Наборы лежат в `evals/datasets/unsafe/` и общие с ролью 7
