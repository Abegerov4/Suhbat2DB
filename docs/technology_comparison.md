# Сравнение технологий

По каждому ключевому решению здесь сравниваются альтернативы; подробное обоснование лежит в [ARCHITECTURE.md](../ARCHITECTURE.md#8-архитектурные-решения-adr). Критерии взяты из [требований](requirements.md): уточнение с паузой (FR-07), детерминированная проверка SQL (FR-09, NFR-01), только чтение (NFR-03), воспроизводимость (NFR-15) и стоимость (NFR-10).

Обозначения: ✅ хорошо подходит; ⚠️ подходит с оговорками; ❌ не подходит.

## 1. Оркестрация агента

| Критерий | LangChain (цепочки LCEL) | CrewAI / AutoGen | Собственный цикл на asyncio | **LangGraph** |
|---|---|---|---|---|
| Цикл самокоррекции с лимитом | ❌ | ✅ | ✅ | ✅ |
| Пауза для ответа человека, переживающая перезапуск | ❌ | ⚠️ ввод человека без сохранения между HTTP-запросами в стандартной конфигурации | ⚠️ писать самим | ✅ `interrupt()` + checkpoint в PostgreSQL |
| Маршрут выбирает код, а не LLM | ✅ | ❌ решают агенты | ✅ | ✅ route-функции |
| Стриминг шагов в UI | ⚠️ | ⚠️ | ⚠️ писать самим | ✅ |
| Трассировка из коробки | ✅ | ⚠️ | ❌ | ✅ |

Выбран LangGraph: только в нём пауза для уточнения и продолжение после перезапуска работают без собственного кода. [ADR-020](../ARCHITECTURE.md#adr-020-оркестрация-агента-langgraph-а-не-crewai-autogen-или-собственный-цикл)

## 2. Проверка SQL

| Критерий | Регулярные выражения | LLM-критик (вторая модель) | Только права СУБД | **AST (sqlglot) + EXPLAIN + права СУБД** |
|---|---|---|---|---|
| Устойчивость к маскировке (`DeLeTe`, кавычки, CTE с `DELETE`) | ❌ | ⚠️ вероятностно | ✅ | ✅ |
| Сверка со схемой и подсказка для исправления | ❌ | ⚠️ без гарантий | ❌ только ошибка СУБД | ✅ похожие столбцы и таблицы |
| Детерминированность, воспроизводимость | ✅ | ❌ | ✅ | ✅ |
| Защита от тяжёлых запросов до выполнения | ❌ | ⚠️ | ⚠️ только тайм-аут | ✅ оценка плана |
| Стоимость и задержка | ✅ | ❌ +1 вызов LLM | ✅ | ✅ < 3 мс без БД |

Выбрана проверка по AST вместе с анализом плана и правами СУБД. На наборе из 88 атак заблокированы все, а из 42 безобидных запросов не заблокирован ни один. [ADR-011](../ARCHITECTURE.md#adr-011-проверка-sql-по-ast-sqlglot-а-не-регулярными-выражениями), [ADR-008](../ARCHITECTURE.md#adr-008-проверка-только-чтение-по-правам-роли-а-не-пробной-записью), [validator.md](validator.md)

## 3. Хранение векторного индекса

| Критерий | pgvector в БД приложения | Chroma / FAISS в процессе | **Qdrant** |
|---|---|---|---|
| Гибридный поиск (смысл + точные имена) | ⚠️ dense есть, лексическую часть пришлось бы собирать на `tsvector` | ⚠️ только dense | ✅ dense + sparse с IDF, RRF одним запросом |
| Фильтр по источнику данных | ✅ | ⚠️ | ✅ индекс по payload |
| Индекс отделён от служебных данных | ❌ | ⚠️ | ✅ |
| Число сервисов | ✅ без нового | ✅ без нового | ⚠️ +1 контейнер |

Выбран Qdrant. На небольшом объёме pgvector справился бы не хуже, и решили дело встроенный sparse-поиск и то, что индекс хранится отдельно от служебных данных. [ADR-021](../ARCHITECTURE.md#adr-021-векторный-индекс-qdrant-а-не-pgvector), [ADR-015](../ARCHITECTURE.md#adr-015-schema-linking-text-embedding-3-large-гибридный-поиск-все-кратчайшие-пути-join)

## 4. Взаимодействие компонентов

| Критерий | WebSocket | Опрос (polling) | **REST + SSE через BFF** |
|---|---|---|---|
| Поток шагов агента и токенов ответа | ✅ | ❌ задержка | ✅ |
| Совместимость с HTTP-прокси и авторизацией cookie | ⚠️ отдельный протокол | ✅ | ✅ обычный HTTP |
| Двусторонний канал | ✅ (не нужен: ответ на уточнение приходит отдельным запросом) | — | ⚠️ только сервер → клиент |
| Сложность | ⚠️ состояние соединения | ✅ | ✅ |

Выбраны REST и SSE. Браузер обращается только к Next.js, а тот хранит JWT в httpOnly-cookie. [ADR-017](../ARCHITECTURE.md#adr-017-backend-for-frontend-и-jwt-в-httponly-cookie), [ADR-010](../ARCHITECTURE.md#adr-010-sse-ответ-формируется-вручную), [ADR-019](../ARCHITECTURE.md#adr-019-ход-агента-не-зависит-от-соединения)

## 5. Модели LLM

| Критерий | Одна сильная модель на все узлы | Рассуждающая модель (o-серия, gpt-5) | Открытая модель локально | **gpt-4.1 для точных узлов + gpt-4.1-mini для остальных** |
|---|---|---|---|---|
| Качество генерации SQL | ✅ | ✅ | ⚠️ ниже на сложных запросах | ✅ |
| `temperature` для экспериментов | ✅ | ❌ не принимает | ✅ | ✅ |
| Стоимость вопроса | ⚠️ | ❌ выше | ✅ без оплаты API, но нужна GPU | ✅ $0,008–0,012 |
| Задержка | ✅ | ❌ выше | ⚠️ зависит от железа | ✅ медиана 4–5 с |

Модель выбирается для каждого узла отдельно, резервный провайдер Anthropic. Сравнение с другой моделью запланировано в эксперименте 5. [ADR-014](../ARCHITECTURE.md#adr-014-модели-llm-gpt-41-для-точных-узлов-gpt-41-mini-для-остальных)

## 7. Платформа backend и frontend

| Решение | Альтернативы | Выбор и причина |
|---|---|---|
| Backend | Django + DRF; Node.js (NestJS) | **FastAPI**: асинхронность для LLM и SSE, Pydantic-схемы общие с structured output агента, экосистема Python для LLM и sqlglot |
| Frontend | SPA на Vite + React; Streamlit | **Next.js 16**: серверные маршруты как BFF (токен не попадает в браузер), React-экосистема (shadcn/ui, Recharts). Streamlit проще, но не даёт контроля над безопасностью сессии и интерфейсом чата |
| СУБД | MySQL; SQLite | **PostgreSQL 17**: роли и read-only транзакции, `EXPLAIN (FORMAT JSON)`, хранение checkpoints LangGraph; Spider и BIRD перенесены из SQLite с проверкой результатов |
